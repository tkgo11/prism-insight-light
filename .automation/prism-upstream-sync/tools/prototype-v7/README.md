# Offline audit/checkpoint prototype

Run `node --test .automation/prism-upstream-sync/tools/prototype-v7/tests/*.test.mjs`. The CLI accepts JSON and prints one JSON result: `node .automation/prism-upstream-sync/tools/prototype-v7/maintenance-engine.mjs select input.json`. The input object contains `repo` (local repository with both frozen commits), `state` (actual v4 latest-run), `manifest`, and `observed` (`state_sha`, `head_sha`, `base_sha`, `pr_head_sha`, `pr_base_sha`, and `lock`). `prepare` accepts `state`, `next_state`, `observed`, `recheck`, `previous_manifest`, and `next_manifest`; it only prepares a CAS instruction and never creates a Git tree, commit, or remote ref. `reconcile` accepts a version 1 intent with `kind` (STATE_CHECKPOINT or CODE_MUTATION), run/owner/purpose, original/candidate state SHA, original/candidate code HEAD, base SHA, and SHA-256 of the exact expected checkpoint content. Observations must include state and branch refs, separate PR HEAD/base, lock identity, and, to verify persisted content, the actual content string. It classifies incomplete ref changes, metadata lag, foreign locks, digest mismatches, and restarts without performing writes. The digest covers only the supplied content; it does not independently prove completeness of a tree. Re-read refs and lock immediately before any externally implemented mutation and verify actual contents afterwards. An adapter must demonstrate atomic CAS, not merely a read followed by an update. This prototype cannot perform that transaction or acquire/release a lock.

This is a conservative, incomplete offline prototype, not an operational scheduler or certification system. It cannot authenticate a scheduled worker, verify independent execution/artifact provenance, validate actual test logs, or establish that a candidate contains a complete checkpoint. It rejects all new PASS records pending a trusted independent verifier; existing historical PASS records are not independently validated or counted by `applyAuditRecord`. HELD/DEFECT can be revisited only with an explicit `supersedes` hash (`recordId`), a new run ID, and changed evidence. Source and JSON supplied by a caller are not a trust boundary. `select` verifies the inventory against a local Git tree, but its selection function alone is not a proof of current CI, independent certification, or merge readiness. No merge command exists.

No GitHub Actions workflow is installed or activated: an Actions backend would need separately reviewed least-privilege credentials, durable intent, artifact authentication, CAS support, and recovery tests. A scheduled ChatGPT worker without a shell cannot execute this CLI directly; a reviewed adapter would need to read the pinned source and inputs, run the engine in an isolated environment, and return authenticated artifacts. None is implemented here. Keep the existing worker_v5 and historical evidence intact; do not replace state or claim audit completion using this prototype alone.

After two reported stalls, task selection chooses only explicitly independent actionable queue entries (`independent_of` contains the stalled work ID), sorted by priority and work ID. Without such a declaration it returns STALLED; it does not infer independence from names or status.

Backend investigation: GitHub REST update-ref does not itself offer a documented atomic expected-SHA precondition. Do not assume a connector wrapper provides atomic CAS without a verified backend guarantee. GraphQL createCommitOnBranch supports expectedHeadOid but creates the commit as part of the operation, so it is not interchangeable with updating a ref to a pre-created commit; permissions, atomicity, tree completeness, and recovery still require proof. GitHub Actions permissions were inaccessible (HTTP 403) in the coordinating session; no backend was activated or tested against that service.

The offline `evidence` command takes `{artifact, expected, history}`. Schema 1 artifacts contain `spec_id`, `spec_sha256`, exact `argv`, `head_sha`, `base_sha`, `round`, `execution_id`, `run_id`, `producer`, integer `exit_code`, `stdout`, and `stdout_sha256`. `expected` supplies independently pinned head, base, round and spec digest. Obtain the pin using the exported `specDigest` against the reviewed source; never take a pin only from the artifact producer. The only compiled-in commands are `git rev-parse HEAD` and the exact Node engine test command; the latter must contain the exact named TAP tests and a zero-failure summary. The interface executes neither command and performs no network access. `history` is a caller-supplied complete execution-ID history; cross-scope reuse is rejected, but an omitted or fabricated history cannot be detected.

Run `node .automation/prism-upstream-sync/tools/prototype-v7/maintenance-engine.mjs evidence artifact-input.json`. Even a consistent artifact returns `CONSISTENT_UNTRUSTED` and `NOT_GRANTED`: the input producer can fabricate stdout, exit code, checkout, history and digest, and matching a pinned command spec does not prove execution or isolation. A trusted collector must separately establish producer identity, source checkout, offline isolation, execution ID uniqueness, complete history, and integrity of captured output. This interface does not grant PASS or certification and is not an Actions adapter.

Local crash-recovery prototype: `persist-intent` takes `{path,intent}` and `load-intent` takes `{path}`. In a pre-existing, trusted local directory, the writer creates a private temporary file, writes and fsyncs it, atomically creates the immutable destination with a same-filesystem hard link, fsyncs the directory, and reads it back. Existing identical intents are idempotent; conflicting contents, symlinks and corrupt files fail closed. Unexpected temporary files from a crash are ignored and not automatically deleted. The SHA-256 checksum detects accidental modification; it is unkeyed and does not authenticate a malicious actor. Use a private directory with access controlled by the operating system; directory replacement, hostile writers, filesystem/OS durability semantics and untested platforms remain out of scope. Actual power-loss durability has not been verified. The in-memory `createMockCas` is for tests only; it is neither a durable ref nor a GitHub adapter and proves nothing about a remote API. Persisting an intent does not acquire a lock, make a remote write, or verify completion.
